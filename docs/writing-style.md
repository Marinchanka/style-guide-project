
# Стиль изложения

Техническая документация должна быть точной, понятной и последовательной. Основная задача текста — помочь читателю разобраться в работе программного продукта или выполнить необходимые действия.

## Основные правила

1. Используйте нейтральный деловой стиль. Избегайте разговорных выражений и эмоциональных оценок.
2. Формулируйте инструкции в повелительном наклонении.
3. По возможности используйте активный залог вместо пассивного.
4. Выражайте одну основную мысль в одном предложении.
5. Избегайте неоднозначных формулировок без пояснения.
6. Объясняйте специальные термины при первом упоминании.
7. Не дублируйте информацию, если на неё можно дать ссылку.

## Примеры

### Формулирование инструкций

**Не рекомендуется:**

> Для осуществления процесса запуска приложения необходимо предварительно произвести установку всех требуемых зависимостей.

**Рекомендуется:**

> Перед запуском приложения установите необходимые зависимости.

### Активный залог

**Не рекомендуется:**

> После установки зависимостей должен быть выполнен запуск сервера.

**Рекомендуется:**

> После установки зависимостей запустите сервер.

### Однозначность

**Не рекомендуется:**

> При необходимости настройте соответствующие параметры.

**Рекомендуется:**

> Если приложение использует внешнюю базу данных, укажите параметры подключения в файле конфигурации.

### Объяснение терминов

**Не рекомендуется:**

> Настройте CI/CD перед публикацией проекта.

**Рекомендуется:**

> Настройте непрерывную интеграцию и доставку (CI/CD) — автоматическую проверку и подготовку изменений к публикации.
