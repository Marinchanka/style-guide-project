# Терминология и глоссарий

Единая терминология помогает избежать неоднозначности и делает документацию понятнее.

## Основные правила

1. Используйте один основной термин для одного понятия.
2. Объясняйте специфические термины при первом упоминании.
3. Сохраняйте оригинальные названия технологий и программных продуктов.
4. Избегайте разговорных сокращений.
5. Используйте одинаковые варианты перевода терминов.
6. Добавляйте новые понятия в глоссарий по мере развития проекта.

## Пример использования терминов

**Не рекомендуется:**

> Отправьте изменения в репу и создайте ПР.

**Рекомендуется:**

> Отправьте изменения в репозиторий и создайте Pull Request (PR).

После первого упоминания можно использовать сокращение PR.

## Глоссарий

| Термин | Определение |
| --- | --- |
| API | Программный интерфейс приложения, обеспечивающий взаимодействие программных компонентов. |
| CI/CD | Подход к автоматизации интеграции, проверки и доставки изменений программного обеспечения. |
| Git | Распределённая система контроля версий. |
| GitHub | Платформа для хранения Git-репозиториев и совместной разработки. |
| Markdown | Язык разметки для оформления текстовых документов. |
| MkDocs | Генератор статических сайтов документации на основе Markdown. |
| Pull Request | Запрос на включение изменений из одной ветки в другую с возможностью проверки и обсуждения. |
| README | Документ с основной информацией о программном проекте. |
| Репозиторий | Хранилище файлов проекта и истории их изменений. |
| Стайлгайд | Набор правил и рекомендаций по созданию и оформлению материалов. |
| Виртуальное окружение | Изолированная среда Python, позволяющая устанавливать зависимости отдельно для каждого проекта. |

## Добавление новых терминов

При появлении нового термина необходимо:

1. Проверить, отсутствует ли он в глоссарии.
2. Выбрать единое название.
3. Сформулировать краткое определение.
4. Добавить термин в таблицу.
5. Проверить его использование в других разделах документации.
