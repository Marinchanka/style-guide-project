
# Доступность документации

Доступность документации — это возможность пользоваться
материалами независимо от особенностей восприятия,
используемого устройства и способа взаимодействия с сайтом.

При подготовке технической документации необходимо учитывать
потребности пользователей, в том числе людей с нарушениями
зрения и другими ограничениями.

## Структура и навигация

1. Используйте один заголовок первого уровня на странице.
2. Соблюдайте последовательную иерархию заголовков.
3. Выбирайте понятные названия разделов.
4. Разделяйте длинные тексты на небольшие смысловые блоки.
5. Используйте списки для перечислений и последовательностей действий.

Заголовки должны отражать содержание раздела, а не
использоваться исключительно для визуального оформления.

## Альтернативный текст изображений

Каждое информативное изображение должно иметь альтернативное
текстовое описание (alt-текст).

Описание должно передавать смысл изображения, а не просто
повторять его название.

**Не рекомендуется:**

```markdown
![Картинка](images/architecture.png)
```

**Рекомендуется:**

```markdown
![Схема взаимодействия клиента, API и базы данных](images/architecture.png)
```

Если изображение содержит важную информацию, которую сложно
передать кратким alt-текстом, добавьте пояснение в основном тексте.

## Оформление ссылок

Текст ссылки должен объяснять, куда она ведёт.

**Не рекомендуется:**

```markdown
[Нажмите здесь](installation.md)
```

**Рекомендуется:**

```markdown
[Инструкция по установке](installation.md)
```

Не используйте одинаковый текст для ссылок с разным назначением,
если это может запутать пользователя.

## Цвет и визуальное выделение

Не передавайте важную информацию только с помощью цвета.

**Не рекомендуется:**

> Ошибочные параметры выделены красным цветом.

**Рекомендуется:**

> Ошибочные параметры отмечены сообщением «Ошибка»
> и выделены красным цветом.

Проверяйте достаточность контраста текста и фона.

## Таблицы

1. Используйте таблицы только для табличных данных.
2. Добавляйте понятные заголовки столбцов.
3. Избегайте сложных таблиц с большим количеством столбцов.
4. При необходимости поясняйте таблицу в основном тексте.

Не используйте таблицы для расположения элементов страницы.

## Код и команды

Размещайте команды и примеры кода в отдельных блоках
с указанием языка программирования.

Не передавайте инструкции только с помощью скриншотов.
Если на изображении показана команда, продублируйте её текстом.

## Проверка доступности

Перед публикацией документации рекомендуется проверить:

- понятность заголовков и навигации;
- наличие альтернативного текста у информативных изображений;
- информативность ссылок;
- читаемость текста и достаточность контраста;
- возможность понять инструкции без использования цвета;
- корректность отображения документации на мобильных устройствах.
